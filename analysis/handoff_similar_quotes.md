# 引き継ぎ：過去の類似見積の参照

## 最終ゴール

見積を作るときに、過去の見積から **参考になるものを少しだけ（最大5件）** 示し、「なぜ似ているか」「何が違うか」「値段はどうだったか」がひと目で分かるようにする。担当者は、自動で出た値段を過去の実績と照らして判断できる。出した見積は履歴として貯まり、次からの検索対象になる。**LLM APIは使わない。**

達成方法（データの持ち方、検索の方式、画面設計、コード構成）は任せる。途中の確認は不要。

## ユーザーにとっての「似ている」

見積担当者が知りたいのは、見た目の形が似ているかより、**値段を決める要素が近いか** である。優先順は次のとおり。

| 順 | 区分 | 条件 | ユーザーにとっての価値 |
|---|---|---|---|
| 1 | **リピート** | 同じ顧客の、同じ図番（改訂違いを含む） | 前回いくらで出したか、前回から何が変わったか。値段を前回とそろえることは取引上とても大事 |
| 2 | **同じ顧客の近い部品** | 同じ顧客で、作り方が近い | その顧客に出してきた値段の水準が分かる |
| 3 | **他の顧客の近い部品** | 顧客を問わず、作り方が近い | 自動見積の値段が妥当かを実績と比べられる |

図番は顧客ごとに付け方が違うので、**別の顧客の同じ図番は別の部品** として扱う。

「作り方が近い」の判断材料:

| 条件 | 扱い |
|---|---|
| 材質 | ほぼ必須。同じ材質、少なくとも同じ系統（鉄・ステンレス・アルミなど）。系統しか分からない過去データ（「SUS」など）は系統で比べる |
| 板厚 | ほぼ必須。同じ板厚か隣の板厚まで |
| 数量帯 | 重視（例：1〜9、10〜99、100〜999、1000〜）。段取りの割り振りで単価が大きく変わる |
| 大きさ（展開面積） | 重視（例：±30%）。数値がない過去データは比べない（除外はしない） |
| 曲げの数・穴の数 | 中くらい |
| 表面処理・追加加工の組み合わせ | 中くらい |
| 特急 | 表示する（割増が入っているかを見分ける） |
| 見積の時期 | 表示する。古いものは注意（価格水準が違う） |

## 表示

- **最大5件**。リピートがあれば必ず先頭に出す。区分（リピート／同じ顧客／他の顧客）が分かるようにする
- 各件に出すもの：見積日、顧客、図番・改訂、品名、材質・板厚、数量、表面処理・追加加工、単価、結果（受注・失注・未回答）、**似ている理由**、**今回との違い**（例：「材質・板厚同じ、数量 100→50、M4タップ +2」）
- **値段の比較**
  - 今回の単価との差（%）を出す
  - 過去の見積に形状の数値があるときは、その見積の条件を **今のマスターで計算し直した標準単価** と、実際に出した単価の比を求める。その比を今回の標準単価に掛けた「過去の出し値の水準で見た今回の単価」も示す。数量や時期が違っても比べやすくするため
  - リピートで今回との差が大きい（例：±20%超）ときは注意を表示する
- 過去の見積の詳細（元の行の全項目）を開ける
- 画面の設計は任せる。別の画面に移ってもよい
- **過去をもとに今回の単価を自動で書き換えない**（参考として表示するだけ。値段を決めるのは担当者）

## データの保持（設計は任せる。満たすこと）

- **リポジトリ内のファイルとして保持し、コミットする**（方式は任せる）。取り込んだ過去見積も、新しく出した見積も、履歴はリポジトリに残す。Gitで差分が読める形式（CSV、JSON Lines など）が望ましい。SQLite などのバイナリ形式にする場合は、差分が読めないことへの対処（書き出し用のテキスト版を並べるなど）を考える
- テストは、コミットされた履歴を書き換えない（一時的な複製を使う）
- **過去見積の取り込み**：CSV（Excel の書き出しを想定）から取り込める。列名の対応づけができ、欠けた列があっても取り込める。最初に `data/past_quotes/past_quotes_seed.csv` を取り込める
- 取り込むときに、材質・表面処理・追加加工の文字をマスターの別名でコードに対応づける（`MasterLoader.resolve_alias` など）。**元の文字も残す**。対応できないもの（「SUS」のような系統だけのもの、マスターにないもの）は、そうと分かる形で持つ
- **見積書を出力したら、その見積が自動で履歴に入る**（顧客、図番・改訂、品名、条件、解析値、単価、見積日）。今の出力記録（`output/quote_log.csv`）の役割と統合してよい
- 受注・失注を後から記録できる（画面から）
- 1万件程度まで、検索が1秒以内

## 種データ

`data/past_quotes/past_quotes_seed.csv`（2,084件、架空の顧客10社、373の図番がリピート、約37%は形状の数値なし）。作り方と列の説明は [data/past_quotes/README.md](../data/past_quotes/README.md)。

- 評価を終えたゴールデンデータ（STEP・DXF・図面PDFの開発用とホールドアウト）の部品から作った
- `出典` 列は試験用。**検索・表示のロジックで使わない**（実データにはない）

## 受入条件

| 項目 | 条件 |
|---|---|
| リピートを必ず出す | ある見積について、同じ顧客・同じ図番の、より前の日付の見積があれば、必ず結果に入る。種データのリピート全件でテストする |
| 条件を守る | 「作り方が近い」の結果に、材質の系統と板厚の条件を外れたものを出さない（テスト） |
| 件数と説明 | 最大5件。すべてに似ている理由と今回との違いがつく |
| 欠けたデータ | 形状の数値がない過去見積も、図番・材質・板厚・数量などで検索対象になる |
| 参考価格の効果 | 種データの見積のうち形状の数値があるもの（今のマスターで標準単価を計算できるもの）について、それより前の見積だけを過去として検索し、参考見積から推した単価と実際の単価の誤差を、自動見積（標準単価）だけの誤差と比べてレポートに残す。**全体とリピートのそれぞれで、類似見積を使うほうが誤差が小さい** こと |
| 速度 | 種データで検索が1秒以内。1万件に増やしても1秒以内 |
| 取り込み | 種データを取り込める。列の対応づけの例（別の列名のCSV）もテストする |
| 履歴 | 見積書を出力すると履歴に入り、次の検索で出る。受注・失注を記録できる |
| LLMなし | この機能とテストは LLM API を呼ばない |
| 画面 | 見積の画面から使える。画面例の画像を `analysis/` に残す |
| 回帰 | `python -m pytest -q` がすべてパスし、STEP・DXFの評価（`--gate`）も合格のまま |

## 制約

- LLM API を使わない。金額はマスターとルールで決める（参考表示の計算も同じ）
- 正解データ（`golden/`）は変更しない。種データを作り直す場合は `scripts/build_past_quotes.py` を使う
- 種データには実在の会社名・人名・図番を入れない

## 完了時に残すもの

## 対象外（今回はやらない）

- 図面画像や3D形状そのものの類似検索
- LLMによる説明文の生成
- 過去の見積から単価を自動で決めること（表示のみ）
- 複数部品をまとめた見積
