# 図面PDFだけからの見積（形状の概算）

STEP・DXF がなく図面PDFしかないときに、図面から形状の値（板厚・穴数・曲げ数・展開面積・切断長）を概算し、
既存の見積計算（マスターCSVとルール）に渡す。目標は **STEPから出した見積に対して金額の誤差±20%程度**。切断長と展開面積は図面の形から測り、データに当てた式は使わない。
結果は必ず概算（`status="partial"`、`reason_code="PDF_SHAPE_ESTIMATE"`）で、画面の「条件修正」で値を書き換えられる。

## 方式

金額の大部分は切断長（レーザー 3円/mm）と曲げ（500円/か所）で決まる。展開面積は材料費にしか効かず小さい。
切断長と展開面積は **図面に描かれた形から測る**。データに当てた式や係数は使わない（2026-10-16 に式を廃止）。

1. **Claude に1回読ませる**（`src/pdf_shape.py`、既定 claude-sonnet-5）。返させるのは
   - 部品全体の外形寸法（図面に書かれた数字をそのまま。CAD出力のPDFではテキスト層にあるかを照合）
   - 展開図の位置（画像のピクセル座標）、投影図の範囲
   - 曲げ・穴の一覧（数ではなく1つずつ書き出させる）、図面の種類（部品か組立図か）
2. **展開図を画像で測る**（`src/pdf_flat_pattern.py`。LLMを使わない。NumPy・SciPy）。閉じた外形線を探し、
   - 内側の閉じた輪郭を穴、外形を分ける直線（実線）と破線・一点鎖線の並びを曲げ線として数える
   - 外形線の輪郭を追跡（Moore近傍）して折れ線に単純化（Douglas-Peucker、許容1px）し、外周の長さを測る。
     穴は輪郭線の中心線の長さ、展開面積は外形の内側の画素数
   - 曲げ線で展開図を面（パネル）に分け、面の形と曲げ線の位置・向きを残す
   ここまでの長さはページ上の画素。展開図には寸法が書かれず、縮尺も展開図だけ別のことがあるので、図面の縮尺の表示は使わない
3. **展開図を折って縮尺を決める**（`src/pdf_fold.py`）。面を曲げ線で3次元に折り、折った形の外形が図面の外形寸法
   （書かれた数字）と同じ比率になる縮尺 k（px/mm）を探す
   - 曲げ角は、すべて90°から試し、90°以外（30・45・60・120・135・180°）を1か所、曲げが5か所以下なら2か所まで混ぜる。向き（山・谷）も試す
   - 許容差：板厚 + 1mm + 寸法の2% + 2px/k（外形寸法は板の外側、折った形は板の中心なので板厚の半分を引いて比べる）
   - 候補が複数あるときは、曲げ線に沿った長さ（どう折っても変わらない）が書かれた寸法と一致する数、90°以外の曲げの少なさ、
     寸法との差の小ささの順に選ぶ。同点が残れば「縮尺が1つに決まらない」として信頼度を下げる
   - 切断長 =（外周 + 穴の周長）÷ k、展開面積 = 面積 ÷ k²。スキャンの傾きは折る前に直す
4. **展開図がない、測れない、折っても外形寸法に合わないとき**は、Claude にもう1回、投影図から部品を
   「ベース（長方形）と、その辺から曲げたフランジ（先でさらに曲がる面を含む）と穴」として書き出させる（数値は図の寸法）。
   書き出した形を展開（shapely で長方形を合成、フランジの平らな長さ = 長さ − 板厚/2）して切断長と面積を計算し、
   Claude が書いた曲げ角で折った形が外形寸法と合うとき（ずれ4%以内）だけ使う。信頼度は低。
   合わなければ切断長・展開面積は空のままにし、担当者が入れる（金額は出ない）
5. **曲げ数・穴数**は展開図の画像計測、それがなければ拡大した図で Claude が数えた数
6. FAX のようにノイズの多い画像の展開図は測らない（線が点に崩れ、横線・縦線が数mm単位で抜けるため。
   点をつなぎ、孤立点を消す処理を試したが、外周を正しく測れたのは一部だけだった）。4. の方法に回る
7. 板厚は図面の読み取り（`PdfConditionReader`）か登録時の入力。金額は `QuoteEngine` が計算する（LLMは金額に関わらない）

信頼度：切断長・展開面積は、展開図を折って縮尺が1つに決まれば medium、決まらなければ low、投影図から組んだ形は low。
曲げ数・穴数は画像の計測が Claude の数と一致すれば medium、それ以外は low。

## 画面・API

- 図面登録で PDF だけのとき、形状を概算して改訂の `analysis` に保存する。見積の作成時に未推定なら、そこで推定する。
  受付の3段階に合わせ、準備が計画に `shape` を入れ（`platform/drawings.py` の `shape_plan`）、抽出（`src/services/extraction.py`、
  データベースなし。AWS では抽出の Lambda）が読み取りのあとに推定し、保存が改訂に入れる（`store_shape`）
- 見積画面：状態「図面PDFから概算」、形状の表に「図面から推定」、条件修正の「寸法の値」欄に推定値を薄く表示し、上書きできる。
  確認事項に「形状の値は図面PDFからの概算です…誤差の目安は±20%」と、推定の根拠（画像で数えた／LLMが数えた）を出す
- API：`POST /api/drawings/shape-estimates`（`file_id`、`thickness_mm`）で受付、`GET /api/jobs/{id}` で `SheetMetalAnalysis`。
  APIキーがないときは 503 `SHAPE_ESTIMATOR_UNAVAILABLE`（画面では寸法を手入力する従来どおりの動き）
- 環境変数 `PDF_SHAPE_ESTIMATOR`：空（APIキーがあれば使う）、`off`、`recorded:<file.json>`（記録済みの結果を返す。お試しデータと資料の写真用、`docs/scripts/recorded_shape.json`）

## 精度の確かめ方

図面PDFのデータは、図面と同じ部品の STEP を持っている。**STEPの解析値で出した見積を正解**とし、図面PDFだけから出した見積との比を測る
（`scripts/evaluate_pdf_shape.py`。材質・表面処理・追加加工・特急は正解の条件で揃え、形状の違いだけを見る。板厚は与える）。

```
python scripts/evaluate_pdf_shape.py --data pdf_data --workers 8 --gate --report analysis/pdf_shape_eval_latest.md
python scripts/generate_pdf_golden.py --per-level 20 --seed 51 --unseen-ratio 0.2 --out pdf_shape_check
python scripts/evaluate_pdf_shape.py --data pdf_shape_check --workers 6 --gate --hide-examples --report analysis/pdf_shape_eval_seed51.md
```

合否の基準（`--gate`）：金額が±20%以内の図面が全体で90%以上、図面の種類（ベクター・スキャン・FAX・手書き）ごとに80%以上。

| 長さの出どころ | 開発用 300枚 | 別のデータ 100枚 |
|---|---|---|
| 展開図を測った（縮尺は外形寸法から） | 186枚：±20%以内 99.5%、±10%以内 96.2%、中央値 0.8% | 59枚：±20%以内 100%、±10%以内 100%、中央値 0.9% |
| 投影図から組んだ形（外形寸法と照合） | 90枚：±20%以内 83.3%、中央値 8.7% | 28枚：±20%以内 89.3%、中央値 7.6% |
| 測れなかった（担当者が入力） | 24枚 | 13枚 |
| すべて（測れなかった図面は外れに数える） | ±20%以内 86.7%、±10%以内 77.7%、中央値 1.4% | ±20%以内 84.0%、±10%以内 78.0%、中央値 1.0% |
| 測れた図面だけ | ±20%以内 94.2%（276枚中260枚） | ±20%以内 96.6%（87枚中84枚） |

レポートは `pdf_shape_eval_latest.md`（開発用 seed=31）と `pdf_shape_eval_seed51.md`（開発に使っていない seed=51、未知の様式を2割含む）。

- 展開図を測れた図面は、切断長が図面の形からそのまま出るので金額の誤差がほぼ1%以内（開発用の外れ1枚は、曲げ線を1本見落として折り方を取り違えたもの）
- 誤差が大きいのは展開図がない図面で、LLMが投影図から書き出したフランジの長さ・穴の大きさの読み違いがそのまま効く
- **合否の基準（全体で90%以上・種類ごとに80%以上）は満たしていない**：全体 86.7%・84.0%、FAX 65.0%・70.0%。
  測れなかった図面（入力が必要）を外れに数えているため。種類別（±20%以内、開発用・別のデータ）：
  CAD出力 92.7%・88.0%、スキャン 90.0%・85.0%、FAX 65.0%・70.0%、手書き 93.3%・90.0%
- FAX は展開図の線が点に崩れ、横線・縦線が数mm単位で抜ける。点をつなぎ孤立点を消して外周を測る処理を試したが、
  折り方が合った24枚のうち±10%以内は4枚で、採用しなかった（FAXは投影図から組む方法に回る）

経過：2026-10-15 版は、外形寸法・曲げ数・穴数から切断長と面積を出す式（係数は golden_data の STEP に最小二乗で当てたもの）で、
±20%以内は開発用 97.7%・別のデータ 95.0% だった。係数がデータに当てた値で、図面の形に根拠がないため 2026-10-16 に廃止し、上の方式に置き換えた。

## 限界

- 評価はすべて合成の図面。実際の図面（寸法の書き方、汚れ、複数部品、展開図の描き方）での精度は分からない
- 合成図面の生成器では、穴の引出し注記と実際の形状が一致しないことがある（注記の数と STEP の穴数が違う）。
  そのため注記ではなく展開図・投影図に描かれた穴を数えさせている
- 外形寸法の読み違いはそのまま切断長に効く。CAD出力のPDFはテキスト層との照合で検出するが、画像の図面では検出できない
- 1枚あたり約7,500入力・740出力トークン（Claude を1〜2回呼ぶ。展開図を測れないときは2回目で部品の形を書き出させる）。図面の画像を外部APIに送る
- 展開図の縮尺は外形寸法に合わせて決めるので、外形寸法の読み違いは縮尺の誤りとして切断長に効く（折った形が寸法と合わなければ使わない）
